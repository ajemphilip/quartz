# Goals
- Find out whether a library that runs the small Kitten TTS 2 voices in a browser already exists, and whether the licences allow one to be published
- Make a browser turn text into the same sounds as the Python package, so that Kitten 2 says words the way it does on Moo Local
- Publish the result on GitHub for anyone to use
- Offer Kitten 2 as a voice on This device

# Description
Step 36 ran Kitten TTS 2 Nano and Pico in a browser, with the text turned into sounds beforehand by the Python package on the Mac. A browser on its own could not do that part. On the evening of 21 November the maker said that if no browser version existed, one could be published on GitHub, as long as the licences allow it. None existed and the licences allow it. The library was written, checked against the Python package and published that evening as `kitten-tts-2-browser`. On the morning of 22 November the maker asked for it to be wired into This device, where Kitten 2 is now a voice model that each device can choose.

# How it works
## What was there and what the licences say
The maker of Kitten published a web package in May 2026. It carries the first Kitten only, and so do the other packages for browsers, among them the one This device uses for phones since step 35. Three apps were found that run a small Kitten 2 inside their own pages. One turns the text into sounds with espeak, one with a word list and letter rules, one with a phonemiser of its own. None of them is a library that another page can load. One is proprietary and one has no licence.

| Part | Licence | Consequence |
|---|---|---|
| Kitten TTS 2 Nano, Pico and Mini, their voices and word lists | Apache 2.0 | May be used and passed on. The library does not copy them, the page fetches them from the maker's own repository |
| The large Kitten TTS 2 of 1.7 billion parameters | A community licence of its maker with conditions | Left out. It is also far too large for a browser |
| kittenml, the Python package | Apache 2.0 | May be rewritten in another language if the source is named |
| misaki, the dictionary and its rules | Apache 2.0 | The same. Its two dictionaries are shipped with the library |
| spaCy and its small English model | MIT | The same. The tagger's numbers are shipped with the library |
| num2words, which writes numbers as words | LGPL | Not used. The wording of numbers was written anew from what the package gives out, without reading its code |

## The text side in four layers
The small Kitten 2 models are single files that a browser runs as they are. What turns text into the sounds the model is given is Python code in four layers, and each was rewritten in JavaScript.

| Layer | What it does | From |
|---|---|---|
| Normaliser | Writes numbers, dates, money, times and abbreviations as words | kittenml |
| Tokenizer and tagger | Cuts the text into words and gives each its word class, so that "read" sounds different in "I read it yesterday" and "I will read it" | spaCy |
| Dictionary and rules | 183,000 words with their sounds, the stress, the endings -s, -ed and -ing, and small words such as "a", "the" and "to" that change with what follows | misaki |
| Unknown words | CMUdict, a list with many names, and after it a small model that guesses | kittenml |

The tagger is not an imitation. The numbers of spaCy's own tagger were taken out of its English model, 6.3 MB, and its small network is computed in JavaScript, so the word classes are spaCy's own. The small model for unknown words is computed the same way, straight from the file in Kitten's repository. Neither needs a second runtime in the page. The speech model itself runs on onnxruntime-web on the processor.

## The same sounds as Python
The speech models were trained on text that went through the Python code, so the aim was the same sounds for the same text, oddities included.

| What was compared with Python | Amount | Result |
|---|---|---|
| Words, word classes, written out text and sounds | 507 sentences kept with the library and 10,785 further lines from the workbook notes, manual pages and made up text, 331,220 words and marks | The same in every case |
| Words no dictionary has | 626 names, made up words and odd strings | The same |
| Numbers, dates, money and abbreviations | 260,000 made up strings and 2 million short ones | The same, apart from the few on which Python itself stops with an error |
| Audio | 48 recordings of the three models | 0.7 dB from Python's on average. Two runs of Python differ by 0.3 dB, another voice by 31 dB |
| By ear, in a way | Whisper wrote down recordings of all three models | Every word right, numbers, money and dates included |

The model adds its own noise, so two recordings never match sample for sample, in Python as little as here. In 8 of the 48 recordings the length differed by one frame of 25 ms. Given the same input, the browser's build of the runtime rounded one predicted length differently from the Mac's build.

Where the Python code stops with an error on malformed text, the library leaves that part as it is and goes on.

## A fault of Safari found on the way
Safari's JavaScript engine reads one kind of pattern wrongly when a character from outside the basic set, such as a rare Chinese character, stands in front of a mark. With the patterns as first written it cut 68 of 1,210 such test texts differently from Chrome. The patterns were rewritten in a form both engines read alike. Ordinary English was never affected. The usual tests run in Node, which shares Chrome's engine and cannot show such a fault, so the text side was also run under Safari's engine on the Mac. All 507 sentences came out the same.

## Published
| What | Where |
|---|---|
| Code, version 0.1.0, Apache 2.0 | `github.com/ajemphilip/kitten-tts-2-browser` |
| Demo page | `ajemphilip.github.io/kitten-tts-2-browser/demo/` |
| For another page to load | `cdn.jsdelivr.net/gh/ajemphilip/kitten-tts-2-browser@v0.1.0/src/index.js` |

One call turns text into a sound file, and a second way keeps the model for more control. The page names itself unofficial and credits Kitten's maker. A notices file lists every work the library is built on with its licence. A first visit with the Nano fetches about 55 MB: the model of 17 MB, its voices of 5 MB and the word list with the small model of 6 MB from Kitten's repository, the tagger and the dictionaries of 13 MB from the library, and the runtime. The browser keeps them for the next visit.

| Model | Speech made, against the time it takes to speak it |
|---|---|
| Pico | About 5 times faster |
| Nano | 5 to 6 times faster on a quiet Mac, as in step 36. About 2.5 times on the evening of 21 November, when the Mac was busy with other work |
| Mini | 2 to 5 times slower. Not for a browser |

Turning a sentence into sounds takes about 0.03 s.

How a web page uses the library, from its README. The first form makes one sound file in one line. The second loads a model once, shows the sounds given to the model, and makes speech that can be played piece by piece.

```js
import { textToSpeech } from 'https://cdn.jsdelivr.net/gh/ajemphilip/kitten-tts-2-browser@v0.1.0/src/index.js';
const wav = await textToSpeech('Once upon a time, a little cow lived on a green hill.', { voice: 'Eleanor' });
new Audio(URL.createObjectURL(wav)).play();
```

```js
const tts = await KittenTTS2.load({ model: 'nano', weights: 'int8' });
tts.phonemize('I read 3 books.');                 // ['ˌI ɹˈɛd θɹˈi bˈʊks.']
const audio = await tts.generate('Hello there.', { voice: 'Otis', speed: 1.1 });   // Float32Array, 24 kHz
for await (const part of tts.stream(longText)) play(part);
```

## Kitten 2 on This device
The website loads the library from the address above when a device chooses it. "Voice model on this device" has two new entries, Kitten 2 Pico and Kitten 2 Nano. "Voice on this device" then lists the voices of that model, four in the Pico and ten in the Nano. Eleanor is first in both. It is the voice of the Instant tier.

- The whole text of a speak job is spoken at once. The first Kitten had to be given one sentence at a time (step 35). Kitten 2 pauses at a full stop by itself
- It runs on the processor, so it takes no graphics memory from the story model
- The model is let go when another voice model is chosen, and in the one at a time mode when another model needs the room
- Automatic is unchanged, the first Kitten on iPhone and iPad and Kokoro on computers. Kitten 2 has to be chosen on the device, because it has not run on a phone yet

# Critical Reflection
## Kitten 2 in a browser
**Pros**
- One of the voices the maker ranked highest now runs in a web page, with nothing installed
- The sounds are those of the Python package, checked on about 11,000 lines, so the voice says a word the same way in the browser and on Moo Local
- It does not use the graphics chip, which on a phone is already full with the story model
- It is published with every source named, so others can use it and check it
- The work found a fault in Safari's engine that the usual tests cannot show, before it reached a phone

**Cons**
- It has not been heard on a phone, and the phone was the reason for the work. On the iPhone it has to share the page's memory with the story model and Whisper
- English only. The other languages of these models need espeak, which the library does not have
- The oddities of the original are copied. A capital letter before a full stop is taken for an abbreviation, so in "This is the letter C. It has two dots" the sounds given to the model have no full stop after the C. Moo Local's Kitten 2 does the same. The letter game says such lines
- The graphics chip cannot be used. The runtime fails to load these model files there
- The Mini is too slow in a browser
- At run time the voice depends on other people's servers, Hugging Face for the model and jsDelivr for the library and the runtime, until the browser has stored the files
- Automatic still gives a phone the first Kitten, so Kitten 2 has to be chosen by hand on each device
