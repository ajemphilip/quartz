- Make it easy for a parent to use their own computer for Moo's listening, stories and voice
- Reduce the choices on the AI engine screen to the ones a parent needs
- Show every computer that can do the work in one list

# How it works
## Three ways to add a computer
| Way | What the parent does | What happens |
|---|---|---|
| A Mac with Apple silicon | Opens Terminal on that Mac, pastes one line from the screen and presses Return | The Mac fetches the installer from the Moo, installs Moo Local and starts it. The Mac then appears in the list |
| Any other computer or phone | Opens the Moo website in its browser and chooses This device | The browser does the work and the device appears in the list |
| A computer that is not found by itself | Types its address | The Moo saves the address and keeps the computer in the list |

## The installer
The line on the screen is `curl -fsSL http://moo.local:8000/local-ai/install.sh | bash`, with the address under which the parent opened the Moo. The Moo carries a copy of Moo Local and serves the installer and six files from it. The installer checks that the computer is a Mac with Apple silicon and has Homebrew, installs Python 3.12 and Ollama if they are missing, puts Moo Local into the user's home folder with its own Python environment, downloads the Kokoro voice, three Piper voices and the story model Gemma 3 4B, which had the highest score in the test of step 32, and starts Moo Local. It installs the quick voices only. Orpheus, Chatterbox, Qwen3 and Kitten TTS 2 are left out. Nothing is set to start when the Mac starts, and the installer prints the command to start Moo Local again.

How the Moo hands out the installer with its own address in it, from `pi/setup_service/routes/localai.py` as in commit `f142582`. The installer is stored with `__MOO_URL__` in place of the address, and the Moo writes in the address under which the parent opened it, so the Mac fetches the rest of Moo Local from the same Moo.

```python
@router.get("/install.sh", response_class=PlainTextResponse)
def install_script(request: Request) -> str:
    path = _DIR / "install.sh"
    if not path.exists():
        raise HTTPException(status_code=404, detail="Moo Local is not included in this build")
    host = (request.headers.get("host") or "moo.local:8000").split(":")[0]
    # The installer fetches over plain http, which the setup app serves on 8000.
    return path.read_text().replace("__MOO_URL__", f"http://{host}:8000")
```

# Critical Reflection
## One line and one list
**Pros**
- A parent can add a Mac without having the code, with one line that the Moo itself hands out
- The installer comes from the Moo, so the Moo and Moo Local are always the same version
- Three choices are easier to read than four, and every machine that can help is in one place
- A computer that the network search misses can still be added by its address

**Cons**
- The installer has never been run on a fresh Mac. Its first real run will be its first test
- It needs a Mac with Apple silicon and Homebrew, and a parent who is willing to paste a line into Terminal. A Windows or Linux computer can only help through its browser
- The first install downloads about 5 GB and takes several minutes with nothing on the Moo's screen to show progress
- Moo Local still does not start by itself after the Mac restarts
- The installer is fetched over plain http inside the home network and run at once. That is acceptable at home, but it means trusting the device that answers to the name moo.local

## In the maker's words
The maker feels that the terminal is always difficult to use and that it should not be this way. He thinks the terminal could be replaced by something else. He was not sure about the three choices on the AI engine screen, with the local machine among them. He finds the Add a device button of the app better, because it makes clearer how a device can run, and because it shows the current device that is ready and doing the work. He thinks the website works as well but may be a bit tricky. He wants to try Bluetooth, to connect to the Moo through the app or the website, so that connecting is easier than through the home network and more accessible.
