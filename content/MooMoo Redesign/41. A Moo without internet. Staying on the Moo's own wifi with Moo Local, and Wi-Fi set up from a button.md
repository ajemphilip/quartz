# Goals
- Let the parent use the Moo without internet when a computer's Moo Local has its models installed
- Stop the Mac from asking again and again to join a wifi network while it is on the Moo's own wifi
- Make setting up the home wifi a button on the dashboard, not the only way forward

# Description
When the Moo has no home wifi it opens its own network, named `moo-` and four digits. The maker said that on the Mac there is always a popup asking to connect to a wifi network to have internet, and asked whether he could pick running Moo Moo locally once the models are downloaded, with a button to set up the wifi.

The popup comes from macOS. Every system checks for internet by fetching a known page, on a Mac `captive.apple.com/hotspot-detect.html`. On the Moo's wifi every web address leads to the Moo, so the check gets the wrong page, and macOS keeps showing its window and offering other networks. The Moo's website also sent every Moo without wifi straight to Pick your wifi.

On the Moo's own wifi the website now opens the dashboard, which starts with a Wi-Fi card. From there the parent can use the Moo without internet, which works only when the AI engine is a computer with Moo Local and that computer has a story, listening and voice model installed, or tap Set up Wi-Fi. While the Moo is used without internet it answers each system's internet check the way that system expects, so the computer stops asking.

# How it works
## The Wi-Fi card on the dashboard
A Moo found on its own wifi now opens the dashboard at once, from the welcome page and from I'm connected to Moo wifi. This follows the maker's wish that, for now, the Moo's own network goes to the dashboard and the wifi settings live there. A first version of this step had a separate page, How should Moo connect?, between the two; it was removed the same afternoon.

The dashboard starts with a Wi-Fi card.

| What the card shows | When |
|---|---|
| On the home wifi by name, with Change Wi-Fi | The Moo is on a home wifi |
| On Moo's own wifi, no internet, with Use it without internet | The Moo is on its own wifi and the computer's Moo Local has a story, listening and voice model |
| What is still missing, as a list, with Set up Wi-Fi | The Moo is on its own wifi and the AI engine is not a computer with those three models |
| On Moo's own wifi without internet, with Stop using it without internet | Offline use is on |

Set up Wi-Fi opens the wifi list as before, and its Back leads to the dashboard. Over Bluetooth the setup goes on to the wifi list as before, since the phone or computer is then not on the Moo's wifi.

## On the Moo
| Part | What it does |
|---|---|
| `GET /network` | Says whether the Moo is used without internet, whether it has a wifi, and what is still missing for offline use |
| `POST /network/offline` | Turns offline use on or off. Refused, with the missing steps named, until Moo Local answers with a story, listening and voice model installed |
| The configuration | Keeps `network.offline`. A Moo used without internet counts as set up without a home wifi name, so the assistant starts |
| `moo-offline` | A small script run as root. While offline, port 80 on the Moo's own wifi goes to the Moo's service on port 8000 instead of comitup's setup page. It uses iptables when present, otherwise nftables in a table named `moo_offline` |
| The internet checks | The Moo answers Apple's `hotspot-detect.html` with Success, Android's `generate_204` with an empty answer, and Windows' `connecttest.txt` and `ncsi.txt` with their expected text |
| Joining a wifi | Choosing a home wifi turns offline use off and gives port 80 back to comitup |
| At start | If offline use was chosen, the setup service puts the port 80 rule back after a restart |

Because the computer's internet check succeeds, macOS treats the Moo's wifi as a working network and stops showing its window. The computer reaches Moo Local's models on itself, and the Moo reaches the computer over its own wifi.

## Checked on the Mac
| Check | Result |
|---|---|
| The internet check answers | Apple, Android and Windows each get the expected page |
| No engine chosen | Offline use refused, "Choose a computer with Moo Local on the AI engine screen" |
| Moo Local without a voice | "Install a voice under Models on the AI engine screen" |
| All three kinds installed | Offline use turned on, the Moo counts as set up, turned off again |
| In the browser | The welcome page opens the dashboard; the Wi-Fi card turns use without internet on and off, and Set up Wi-Fi opens the wifi list |

The Mac's Moo Local was not running and was not started, so a stand-in that only lists three installed models took its place.

# Critical Reflection
**Pros**
- A Moo works where there is no home wifi, for example on a trip, with only a laptop
- The Mac stops asking to join another wifi while it is on the Moo's wifi
- The wifi becomes a choice the parent can make or change at any time from the dashboard
- Offline use cannot be turned on before the computer can actually do the stories, listening and voice

**Cons**
- The Mac's request for Apple's check page reached the Moo's answer, but the popup itself has not yet been watched to stop with offline use chosen, since the Moo's AI engine was not yet set to the Mac's Moo Local
- The computer must stay on the Moo's wifi, so it has no internet itself while the Moo is used this way
- If the AI engine names the computer by a home network number rather than by its name, the Moo cannot find it on its own wifi until the computer is chosen again on the AI engine screen
