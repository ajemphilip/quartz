# Goals
- Let anyone who builds the device match each of the six motors and six buttons to its braille dot, whatever order they were wired in
- Correct a motor that turns the wrong way without soldering it again
- Leave the cell flat, and the storyteller running again, whenever calibration ends

# Description
In the maker's account the last step of the redesign was a way to calibrate the pins. Six modules that plug into any socket (step 24), six motors whose two wires can be soldered either way round and six buttons on free GPIO pins mean that the wiring of one device cannot be assumed for the next. Instead of a fixed wiring diagram, the setup app asks the person building the device to show the Pi which dot is which.

Calibration has two rounds on one screen. In the first round the app pulses each motor in turn, raising its dot and lowering it again, and asks "Which dot moved?" The person answers with the number of the dot, and ticks "Moved down first (reversed)" when the dot went down before it went up. The app then swaps the two direction pins of that motor, so a motor that turns the wrong way is corrected in software. In the second round the person taps a dot on the screen, its pin rises, and they press the button under that raised pin. The Pi reports which input changed, and that button is matched to the dot. When all six motors and all six buttons are matched, the app writes the pin map into the configuration file on the Pi and shows "Moo's Braille cell is mapped."

The Pi does three things around the two rounds. Starting calibration stops the storyteller if it is running, so the two cannot drive the motors at once. Ending it, saved or not, lowers every dot so the cell is flat. The storyteller then starts again if it was running before, and reads the new map (step 30).

# How it works
## What the phone asks and what the Pi does
| Request | What the Pi does |
|---|---|
| Start | Stops the storyteller if it runs, opens the driver with the current pin map and sends that map to the phone |
| Pulse, cycle | Raises the dot of one motor and lowers it after about a second. Used in the first round |
| Pulse, up | Raises one dot and holds it. Used in the second round |
| Button | Returns the last button that was pressed, if any |
| Save | Writes six motor pin pairs and six button pins, in dot order, into the configuration file. Lowers every dot and starts the storyteller again if it ran before |
| Stop | The same as save, without writing anything |

# Critical Reflection
## Calibration instead of a wiring diagram
**Pros**
- Modules, motors and buttons can be wired in any order, and a reversed motor needs no soldering, which lowers what a builder has to get right the first time
- A module that is swapped or rewired needs a new calibration, not new code
- The cell always ends flat, and the storyteller cannot take the motors while calibration runs

**Cons**
- The first round asks the person to watch which dot moves. A blind builder could feel the dot rise instead, but the wording and the layout of the screen assume sight, and the files do not show a test with a screen reader
- Calibration matches dots to pins but does not measure height. Dot height still depends on the time limit of step 29 and the fit of each printed screw of step 26
- The map lives in one file on the Pi. A factory reset deletes that file, so the device then has to be calibrated again
